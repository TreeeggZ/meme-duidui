# 技术与迭代说明

## 当前实现范围

项目延续大学期间基于PyTorch的桌面情绪匹配原型思路，本次使用AI辅助开发重新实现为微信小程序。表情与手势匹配是核心交互探索，AI整理、标签搜索和图库管理提供配套能力。输入是用户导入的图片文件，尚未直接接入微信收藏表情包；推荐效果与实际使用价值仍需持续验证。

## 模块分工

| 部分 | 作用 |
| --- | --- |
| TypeScript / WXML / WXSS | 原生小程序业务、页面与样式 |
| 本地图库与标签 | 保存素材、收藏和描述，支持搜索与匹配 |
| 视觉模型API | 对用户确认的图片批次生成整理建议 |
| 微信视觉能力及预训练表情模型 | 本机面部检测、形态、表情情绪分类与手势识别 |
| Python | 模型检查与评测工具 |

开发中使用AI辅助编码与排错，根据需求与真机表现调整方案，并通过复测检查修改是否解决实际问题。

## 把AI建议变成可用的图库信息

只收到模型返回的一段文字，并不能完成图片整理。实际流程包括选图、确认发送批次、生成建议、修改与审批、保存，再回图库搜索。

项目把模型输出作为建议处理，保留人工判断环节。已有真实录像覆盖预览、修改、审批和保存；搜索录像来自另一段实际使用，演示中不把两次操作伪装成同一批连续执行。

## 相机目标移除与恢复

早期真机上出现过面部离开画面后检测等待超时的问题。排查时分别检查画面送帧、检测返回与目标移除事件，再调整事件处理、旧会话释放和新帧恢复流程。

面部离开后返回恢复已有真机成功反馈，后续也验证了收起相机预览、滚动候选、展开与停止的基本交互。这些是具体场景的验证，设备兼容与长时间使用仍需持续检查。

## 匹配结果的解释

形态、表情类别与手势是不同输入。界面展示当前可用标签及候选来源，并允许用户锁定候选。锁定状态下保留的结果不被介绍成每一帧都重新推荐。

当前仓库截图中的面部画面只启用了情绪候选；V手势画面展示同动作筛选。更完整流程请看[演示视频](https://www.bilibili.com/video/BV1zTn564EdN/)。
